# 目录上下文索引与写入前置门禁

## 简报

- 解决什么问题：具体项目缺少与代码共置的局部索引，AI 修改文件时无法确定且无法证明已经获得必要前置上下文。
- 这一版做什么：为显式登记的代码根提供可继承的 `.harness-index.json`，并通过单一 `context guard` 在首次写入时返回上下文、生成会话回执、阻断操作，重试时仅在依赖闭包未漂移的情况下放行。
- 暂时不做什么：不猜测源码目录、不分析语言 import 图、不覆盖未登记目录、不证明模型理解了上下文，也不建立第二套平台专属门禁逻辑。

## 用户请求

> 我希望这个项目能在具体项目里面，特别是代码的文件夹下提供索引，然后AI写每个文件的时候依赖前置。这个harness层有做到吗？
>
> 帮我实现这个目标

用户确认的边界：

- 索引目录硬阻断。
- `.harness-index.json` 是目录索引唯一事实源。
- 多层索引按祖先链累加，子层不能删除父层前置。
- 目录默认项作用于全部文件，精确文件项只追加前置，不支持 glob。
- 首次写入被阻断并返回前置上下文，同一会话重试后放行；索引或依赖漂移后回执立即失效。
- `.harness/config.json` 显式登记 `codeRoots`，根外文件保持现有规则。
- 索引与门禁通过单一 `context guard` 接口对 CLI、Hook 和测试暴露。

## 目标

1. 让项目维护者明确声明需要目录上下文门禁的代码根。
2. 让模块索引与代码共置，并以确定性、零第三方依赖的格式描述目录默认前置和精确文件追加前置。
3. 让 AI 在第一次尝试修改受管文件时获得完整、可追溯、顺序稳定的前置上下文，同时阻止该次写入。
4. 让同一会话中的重试仅在索引和全部传递前置内容保持不变时放行。
5. 让 CLI、平台 Hook、检查器和测试复用同一门禁模块及错误契约。

## 非目标

- 不自动猜测 `src`、`app`、`lib` 等代码目录。
- 不解析 JavaScript、TypeScript、Python、Go 等语言的 import 语法。
- 不用向量检索或模型判断生成前置依赖。
- 不对 `codeRoots` 之外的文件增加写入限制。
- 不声称回执能够证明模型理解了上下文；回执只证明 Harness 已把当前内容交付给该会话。
- 不把索引、回执或目录依赖复制进 Slice 状态形成第二事实源。

## 需求条目

| ID | 需求 | 证据 |
| --- | --- | --- |
| REQ-001 | `.harness/config.json` 必须可显式登记零个或多个安全、仓库相对的 `codeRoots`；启用能力时每个根必须存在且被目录索引覆盖。 | 用户选择“显式 codeRoots” |
| REQ-002 | 每个目录索引使用版本化 `.harness-index.json`；支持非空模块摘要、目录默认 `readBeforeWrite` 和按精确相对文件名追加的 `files.*.readBeforeWrite`。 | 用户选择索引格式与文件粒度 |
| REQ-003 | 目标文件的索引从所属代码根到目标目录按祖先顺序累加；子索引和文件项只能追加，不能删除上层前置。 | 用户选择“祖先链累加” |
| REQ-004 | `readBeforeWrite` 只接受指向仓库内文本文件的精确相对路径；拒绝绝对路径、glob、目录、路径穿越、缺失文件、二进制文件和依赖环。 | 已确认共享边界 |
| REQ-005 | 上下文解析必须递归收集前置文件自身命中的索引和前置，去重后按稳定顺序输出，并保留每项来源索引。 | “依赖前置”与确定性门禁要求 |
| REQ-006 | 单一 `context guard` 接口接收目标文件与会话标识，返回 `unmanaged`、`blocked` 或 `allowed` 决策；CLI、Hook 和测试不得各自实现解析规则。 | 用户确认模块接口 |
| REQ-007 | 受管文件首次 guard 必须返回 `blocked`，输出目录索引摘要及完整前置文本，并在仓库外的 Git 私有运行目录生成会话回执；本次写入不得发生。 | 用户选择“首次阻断后重试” |
| REQ-008 | 同一会话、同一目标文件再次 guard 时，只有索引链、依赖闭包及其原始内容摘要均与回执一致才返回 `allowed`。 | 用户选择硬阻断与漂移失效 |
| REQ-009 | 索引、依赖引用或内容发生任何变化后，旧回执必须立即失效；下一次 guard 重新返回 `blocked` 和当前上下文。 | 用户选择漂移立即失效 |
| REQ-010 | 不在任何 `codeRoot` 下的目标返回 `unmanaged` 并保持现有写入行为；位于代码根但未命中索引的目标必须稳定阻断并给出修复动作。 | 用户选择显式覆盖边界 |
| REQ-011 | 检查器必须验证配置、索引 schema、覆盖、引用安全、文本可读性和依赖无环；错误必须包含稳定 ID、目标路径和确定性修复说明。 | 现有 Harness 检查契约 |
| REQ-012 | 平台 Hook 只负责标准化目标文件与会话参数并调用 `context guard`；无 Hook 平台必须提供等价 CLI 入口，不复制领域逻辑。 | 现有 Hook 适配约束 |
| REQ-013 | 回执不得写入受版本控制的工作树，不得包含前置文件正文，只保存验证所需的路径、摘要、会话与目标身份。 | 工作区清洁与最小敏感面约束 |

## 用户故事

1. 作为项目维护者，我希望显式登记代码根，以便 Harness 不会误管文档、生成物或未知技术栈目录。
2. 作为模块维护者，我希望在代码目录旁维护一个索引，以便局部知识随模块移动和审查。
3. 作为 AI Agent，我希望第一次写入前直接收到完整前置内容，以便无需猜测或额外搜索。
4. 作为审查者，我希望看到写入因缺少或漂移上下文而被确定性阻断，以便规则不依赖 Agent 自觉。
5. 作为大型仓库维护者，我希望父目录约束自动传递且不能被子目录删除，以便全局不变量不会静默丢失。
6. 作为文件作者，我希望只为特殊文件声明额外前置，以便公共依赖不必逐文件重复。
7. 作为 Harness 适配者，我希望 CLI 和不同平台 Hook 调用同一个门禁接口，以便跨平台行为一致。
8. 作为安全审查者，我希望索引拒绝越界、二进制和循环引用，以便上下文装载不会成为任意文件读取通道。

## 验收标准

- [ ] 配置未启用 `codeRoots` 时，现有 Harness 行为与测试保持不变。
- [ ] 合法的祖先索引、目录默认项、精确文件项和传递前置能解析为顺序稳定的上下文闭包。
- [ ] 对受管目标的首次 guard 返回非零阻断结果，并在输出中包含来源、路径、摘要和完整文本；目标文件保持未修改。
- [ ] 同一会话立即重试返回允许结果；更换会话或目标仍首次阻断。
- [ ] 修改任一索引或传递前置后，旧回执不再放行并返回更新后的上下文。
- [ ] 未覆盖代码根、非法 schema、缺失引用、目录引用、二进制引用、越界路径和依赖环均以稳定错误拒绝。
- [ ] 代码根之外的文件返回 `unmanaged`，不产生回执也不阻断。
- [ ] Hook 与 CLI 对同一输入给出相同决策和错误 ID。
- [ ] 检查器能够在写入前发现全部静态索引错误。
- [ ] 自动化测试覆盖解析、继承、传递依赖、回执、漂移、路径安全和真实 Hook 首次阻断/重试路径。
