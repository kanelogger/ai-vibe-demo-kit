# Vibe Coding Project Map

本目录层由 ai-vibe-demo-kit 安装到现有项目。应用代码、技术栈和构建系统继续由当前项目拥有。

## 设计目标

仓库同时提供两个闭环：

- 上下文闭环：事实、过程、状态和经验可以被新会话恢复。
- 执行闭环：目标可观察，小版本可运行，门禁、验证和回退可执行。

## 目录职责

```text
.
├── AGENTS.md              # 冷启动索引、高频红线和门禁
├── workflow-state.json    # 唯一机器状态源
├── workflow/              # 本轮决策过程
├── SPECS/                 # 长期有效的项目事实与 feature spec
├── tasks/                 # 当前执行单元
├── memory/                # 决策和 ADR
├── rules/                 # 测试、安全、实现和 Git 规则
├── .agents/               # Skills、Hooks 和路由
└── scripts/               # Kit 状态机和检查入口
```

应用源码、测试、部署和基础设施目录保持原样。把实际位置和命令登记到 `SPECS/ARCHITECTURE.md`，不要为了套件重排现有代码。

## 生命周期

- `workflow/` 解释本轮为何这样做，完成后可以归档。
- `SPECS/` 约束当前实现，必须随代码持续演进。
- `memory/` 保存跨需求仍有价值的经验；新决定覆盖旧决定时写明谱系。
- `rules/` 只保存可复用约束，任务专属信息留在 feature spec 和 tasks。

## 冷启动验收

新会话只读仓库后，应能回答：项目是什么、走到哪一步、允许做什么、按什么流程做、如何验证、经验写到哪里。
