# 项目级 AGENTS.md 模板

项目级 `AGENTS.md` 位于仓库根目录，提供最小、稳定、可执行的项目上下文。它会反复加载，应保持小而聚焦，并通过相对路径指向按需资料。

## 纳入标准

仅纳入几乎所有任务都需要的项目定位、关键安全或数据完整性约束、默认工具无法推导的非标准命令，以及按需文档或 Skill 入口。实时实现细节、一次性纠正和可由代码或配置发现的事实留在仓库中。

## 可复制模板

复制到仓库根目录 `AGENTS.md`，替换所有 `【】` 占位内容，删除不适用章节和本说明。

```markdown
# 项目

【一句话说明项目是什么、服务谁，以及最重要的质量目标。】

## 工具与验证

- 包管理器：`【仅在默认选择不明确时填写】`
- 安装：`【仅填写非标准命令；没有则删除】`
- 构建：`【仅填写非标准命令；没有则删除】`
- 类型检查：`【仅填写非标准命令；没有则删除】`
- 测试：`【项目认可的最小验证命令；没有则写未提供】`
- 【项目有适用 E2E 时填写：开发期间只运行针对性场景；实现完成、准备交付时在最终代码上运行全套 E2E。全套命令、针对性执行方式与工件要求见下方的测试约定。】

## 仓库级约束

- 【适用于整个仓库、可执行且无法从代码可靠推导的规则。】
- 【安全、数据完整性或发布门禁；明确需要批准的动作。】

## 稳定领域概念

- `【术语】`：【只解释长期稳定且容易混淆的项目含义。】

## 按需指南

- 【语言或领域】：`【相对路径】`
- 【测试约定】：`【相对路径】`
- 【固定工作流】：使用 `【Skill 名称或入口】`

## 局部规则

- 进入 `【子目录】` 后，读取该目录的 `AGENTS.md`。
```

初始根文件通常只需要「项目」和「工具与验证」。没有真实内容的章节直接删除。

## 验证与完成

- 开发期间根据改动路径、行为变化和回归风险选择针对性检查，不运行全套 E2E；有适用 E2E 的实现任务在最终代码上交付前运行全套，影响结果的后续改动须重跑。
- 项目启用 E2E 约定前，须在测试规则或 `project.yml#commands.e2e` 填写已核实的全套命令，并说明针对性场景怎么运行；无法运行时报告原因，不伪称通过。
- 文档、无行为变化的配置等低风险可逆改动可使用针对性检查；高风险或发布相关改动遵循对应门禁。
- 完成 = 满足任务验收标准，运行必要的相关验证，处理由本次改动导致的失败，并报告未执行或失败的检查。

## 信息去向

| 信息 | 放置位置 |
| --- | --- |
| 项目定位、非标准命令、全局安全约束 | 根目录 `AGENTS.md` |
| 包或目录专属约束 | 子目录 `AGENTS.md` |
| TypeScript、测试、API 等参考知识 | 独立文档 |
| 有明确触发条件的固定流程 | Skill |
| 实时路径、模块关系和实现状态 | 代码、配置、Schema 或检索工具 |
| 冗余、模糊、一次性规则 | 删除 |

## Monorepo 子目录模板

只有子目录形成独立且稳定的工作范围时，才创建局部文件：

```markdown
# 范围

【一句话说明当前包或目录的职责。】

## 局部约束

- 【只填写进入该范围后才适用的规则。】

## 按需指南

- 【主题】：`【相对路径】`
```

子目录文件与根文件共同进入上下文，不要重复根文件内容。

## 维护入口

规则分类、证据审计、审阅包、备份、并发检测和新上下文验收属于按需的 `.agents/skills/agents-maintenance` Skill。普通任务不加载这些维护步骤。规则重构、用户级规则变更、生产写入、发布和破坏性操作才进入严格审阅与人工批准。
