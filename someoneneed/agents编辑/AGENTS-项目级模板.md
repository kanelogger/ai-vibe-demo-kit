# 项目级 AGENTS.md 模板

项目级 `AGENTS.md` 位于仓库根目录，为进入该仓库的 Agent 提供最小、稳定、可执行的项目上下文。它会在项目会话中反复加载，因此应保持小而聚焦，并通过相对路径指向按需资料。

## 纳入标准

一条信息只有满足以下条件之一，才适合进入项目根文件：

- 几乎所有项目任务都需要。
- 属于安全、数据完整性或发布流程的关键约束。
- 在至少两次独立会话中造成了相同损失，且 Agent 无法从代码或配置可靠推导。
- 用于指向更具体的子目录文件、参考文档或 Skill。

具体文件位置、当前实现细节、可由标准配置发现的信息和一次性纠正不应写入根文件。

## 可复制模板

复制到仓库根目录的 `AGENTS.md`，替换所有 `【】` 占位内容，然后删除不适用的章节和本说明。

```markdown
# 项目

【用一句话说明项目是什么、服务谁，以及最重要的质量目标。】

## 工具与验证

- 包管理器：`【仅在默认选择不明确时填写】`
- 安装：`【仅填写非标准命令】`
- 构建：`【仅填写非标准命令】`
- 类型检查：`【仅填写非标准命令】`
- 测试：`【填写项目认可的最小验证命令】`

## 仓库级约束

- 【只填写适用于整个仓库、可执行且无法从代码可靠推导的规则。】
- 【安全关键规则可保留，即使触发频率较低。】
- 【新增规则应有重复会话证据，不为一次性失败追加规则。】

## 稳定领域概念

- `【术语】`：【只解释容易混淆且长期稳定的项目含义。】

## 按需指南

- 【语言或领域】：`【相对路径，例如 docs/TYPESCRIPT.md】`
- 【测试约定】：`【相对路径，例如 docs/TESTING.md】`
- 【固定工作流】：使用 `【Skill 名称或入口】`

## 局部规则

- 进入 `【子目录】` 后，读取该目录的 `AGENTS.md`。
```

初始文件通常只需要「项目」和「工具与验证」。没有真实需求的章节应直接删除。

## 信息去向

| 信息 | 放置位置 |
| --- | --- |
| 项目定位、非标准命令、全局安全约束 | 根目录 `AGENTS.md` |
| 某个包或目录专属约束 | 子目录 `AGENTS.md` |
| TypeScript、测试、API 等参考知识 | 独立文档 |
| 有明确触发条件的固定流程 | Skill |
| 实时路径、模块关系和实现状态 | 代码、配置、Schema 或检索工具 |
| 冗余、模糊、一次性规则 | 删除 |

## Monorepo 子目录模板

只有子目录形成独立且稳定的工作范围时，才创建局部文件：

```markdown
# 范围

【用一句话说明当前包或目录的职责。】

## 技术栈

- 【只填写该范围独有且无法从配置直接判断的信息。】

## 局部约束

- 【只填写进入该范围后才适用的规则。】

## 按需指南

- 【主题】：`【相对路径】`
```

子目录文件会与根文件共同进入上下文，不要重复根文件内容。

## 维护闭环

1. 固定常驻 Token 预算；把预算视为上限，不是填满目标。
2. 从真实项目会话中提取重复探索、错误命令、用户纠正、规则冲突和过时规则。
3. 只有至少两次独立会话支持时，才把普通缺口视为候选规则。
4. 判断候选内容应进入根文件、子目录、独立文档、Skill，还是删除。
5. 每轮最多执行五处新增、删除、重写或下沉。
6. 新增内容达到预算上限时，必须由删除或下沉其他内容支付成本。
7. 所有修改先展示证据和 diff，由人工决定是否写入。

## 发布前检查

- 根文件是否仍能让 Agent 立即理解项目并运行正确验证命令。
- 每条规则是否稳定、可执行、不可由仓库直接发现。
- 是否存在冲突、重复、过时路径或空泛要求。
- 低频流程是否已经下沉为 Skill 或独立文档。
- 根文件和子目录文件是否重复加载相同内容。
- `AGENTS.md` 与其他 Agent 入口是否保持单一事实源；需要兼容 `CLAUDE.md` 时可使用符号链接，避免维护两份漂移的副本。
