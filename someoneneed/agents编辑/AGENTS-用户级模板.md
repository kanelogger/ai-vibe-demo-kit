# 用户级 AGENTS.md 模板

用户级 `AGENTS.md` 用于保存个人、跨项目、长期稳定的协作偏好。文件位置由 Agent 工具决定，例如 `~/.codex/AGENTS.md`、`~/AGENTS.md` 或 `~/.claude/CLAUDE.md`。

用户级文件由用户手工维护。不要让工具根据单次会话自动重写它。

## 纳入标准

一条指令只有同时满足以下条件，才适合进入用户级文件：

- 跨多个项目都适用。
- 预计长期保持稳定。
- 体现用户自己的判断、取舍或工具偏好。
- Agent 无法仅通过读取当前仓库可靠推导。
- 值得在每次会话中占用上下文。

项目技术栈、构建命令、目录结构、领域术语和局部约束应放入项目级文件或按需文档。

## 可复制模板

复制后替换所有 `【】` 占位内容，并删除不适用的条目和本说明。

```markdown
# 协作约定

## 工作目标

【用一句话说明希望 Agent 如何协助你，以及最重要的质量目标。】

## 决策原则

- 【最重要的取舍，例如：正确性优先于交付速度。】
- 【遇到信息不足时应如何处理。】
- 【何时应主动指出错误前提或高风险方案。】

## 沟通方式

- 【结论、依据和建议的顺序。】
- 【默认语言、语气和篇幅。】
- 【不确定性应如何表达，例如给出概率或明确标记推断。】
- 【常用输出格式，例如只输出步骤、表格、diff 或 JSON。】

## 工作方式

- 【开始工作前必须完成的调查。】
- 【修改既有内容时应优先遵循的原则。】
- 【何时需要先复现问题、制定计划或分析影响范围。】
- 【任务完成前必须覆盖的调用方、文档或其他交付物。】

## 验证标准

- 【行为变更需要什么级别的验证。】
- 【Bug 修复如何证明原问题不再出现。】
- 【无法运行验证时应如何报告。】

## 工具偏好

- 【跨项目稳定存在的命令或工具偏好。】
- 【特定类型任务应优先使用的工具。】
- 【禁止使用或只在特定条件下使用的工具。】

## 安全边界

- 【删除、覆盖、发布、推送或修改外部系统前的要求。】
- 【如何处理与当前任务无关的已有改动。】
- 【不得读取、写入或泄露的数据范围。】

## 文件维护

- 不要自动修改本文件；只有用户明确要求时才提出或执行修改。
- 项目事实和项目专属规则以仓库内的项目级 `AGENTS.md` 为准。
```

## 删除项

以下内容不应保留在最终文件中：

- `【】` 占位符和示例说明。
- 「写出干净的代码」等不可验证的常识。
- 只适用于某个仓库的命令、路径和技术栈。
- 为一次性失误追加的防御性规则。
- 与 Agent 系统指令或工具内建能力重复的说明。
- 含义相同但表述不同的重复规则。

## 维护方法

- 只在个人偏好发生真实变化时更新。
- 新增规则时同步删除重复或低价值内容。
- 定期检查冲突、过时工具偏好和长期未使用规则。
- 用户级文件不参与基于项目会话记录的自动训练。项目级规则应在项目内部单独维护。
