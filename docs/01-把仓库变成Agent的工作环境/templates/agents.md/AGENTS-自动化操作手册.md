# AGENTS.md 自动化操作手册

本手册是 Agent 规则维护的入口。普通开发、文档和只读任务不需要加载完整维护流程；只有规则文件本身需要创建、重构、审计或验证时，才按本手册路由到 `.agents/skills/agents-maintenance` Skill。

## 适用范围

启动维护 Skill 的场景：

- 创建或重构用户级、项目级或局部 `AGENTS.md`；
- 根据多次会话证据精简冲突、重复、过时规则；
- 验证规则作用域、按需加载和新上下文行为。

不授权 Agent 自动改写用户级规则、联网补充项目事实，或未经批准提交、推送、发布和修改外部系统。

## 两种模式

### 普通模式

适用于只读审计、仓库内可逆编辑、无生产访问的本地测试、低风险文档或规则整理。Agent 可在用户已授权的范围内连续完成调查、实现、相关验证和失败修复。Reviewer、Verifier、审阅包和人工批准仅在用户明确要求或改动升级为高风险时启用。

### 严格模式

适用于用户级规则变更、生产写入、发布、外部系统变更、破坏性操作，以及需要备份、并发检测或新上下文验收的规则重构。严格模式必须经过独立语义审阅和一个人工批准门。

## 路由步骤

1. **确认作用域**：发现当前仓库根目录、实际用户级目标和相关局部入口；不要求用户替换路径占位符。
2. **按需读取**：只读取与任务相关的模板、目标文件、直接引用和项目配置。不要默认读取整套环境或维护资料。
3. **分类与起草**：逐条决定保留、重写、迁移到用户级/项目级/局部规则/文档或 Skill，或删除；项目事实必须有来源，草稿不得含未解析占位符。
4. **确定性检查**：检查标题、空章节、作用域、重复、冲突、引用路径、命令可解析性和敏感信息。
5. **选择风险门**：普通模式可继续完成可逆本地工作；严格模式生成规则来源图、分类表、完整草稿、diff、哈希和独立审阅结果。
6. **写入与验证**：严格模式在批准后重新检查源文件哈希，备份目标，原子写入，读回比对哈希并执行确定性检查；发生并发变化时停止，不覆盖新内容。
7. **完成报告**：报告实际路径、改动、验证结果、未执行或失败的检查，以及仍需用户处理的事项。实现类任务的完成定义为：满足验收标准、运行必要验证、处理本次改动导致的失败并如实报告。

## 安全门禁

- 删除、覆盖、提交、推送、发布、生产写入和外部系统变更需要用户明确授权。
- 备份只在严格模式和确有写入风险时执行；备份失败则不写入。
- 用户级规则始终需要用户批准；项目内普通可逆编辑可在已有任务授权下继续。
- 不能启动独立 Reviewer 或 Verifier 时，标记为“未独立验证”，不得声称通过。

## 按需资料

详细的审阅包格式、安全写入与备份、并发检测、哈希和新上下文验收应放在 `.agents/skills/agents-maintenance/` 的 Skill 及其 references 中。调用时只加载对应章节：

- 规则分类和审阅包：`references/review-package.md`；
- 高风险写入、备份和恢复：`references/safe-write.md`；
- 新上下文验收：`references/verification.md`。

若目标仓库尚未提供这些入口，先完成只读调查并报告缺失项；不要把长流程复制回常驻 `AGENTS.md`。

## 停止条件

- 调查任务：已回答问题并列出证据和未知项；
- 草稿任务：已生成完整草稿、diff 和检查结果；
- 严格维护任务：审阅包通过批准后完成写入、读回和验证；
- 任一任务：遇到无法确认的作用域、并发修改、真实偏好冲突或缺失授权时暂停并报告。

本文件只描述路由和门禁。模板说明、示例和占位符不得直接写入目标 `AGENTS.md`。
