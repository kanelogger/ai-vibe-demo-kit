# 用户级 AGENTS.md 模板

用户级 `AGENTS.md` 保存跨项目、长期稳定的个人协作偏好。文件位置由 Agent 工具决定，例如 `~/.codex/AGENTS.md` 或 `~/AGENTS.md`。用户手工维护该文件；Agent 只有在用户明确要求时才提出或执行修改。

## 纳入标准

一条指令适合进入用户级文件，需同时满足：

- 跨多个项目适用，并预计长期稳定；
- 体现用户自己的判断、取舍或工具偏好；
- Agent 无法从当前仓库可靠推导；
- 每次会话都值得占用少量上下文。

项目技术栈、命令、目录结构、领域术语和局部约束放入项目级文件或按需文档。

## 可复制模板

复制后替换所有 `【】` 占位内容，删除不适用章节和本说明。

```markdown
# 协作约定

## 工作目标

【一句话说明希望 Agent 如何协助，以及最重要的质量目标。】

## 决策原则

- 【重要取舍，例如正确性优先于速度。】
- 【信息不足时的处理方式。】
- 【发现错误前提或高风险方案时的处理方式。】

## 沟通方式

- 【结论、依据和建议的顺序。】
- 【默认语言、语气和篇幅。】
- 【不确定性如何表达。】

## 工作方式

- 默认读取完成任务所需的文件并继续执行；只有缺失信息会实质影响正确性时才提问。
- 修改既有内容前读取相关来源，保持改动小、可追溯并与现有约定一致。
- 涉及服务边界、发布或外部系统时，按需读取对应项目文档或 Skill。

## 验证标准

- 根据行为变化和回归风险选择最小有效检查；已有覆盖足够时复用现有检查。
- 文档、配置和低风险可逆改动可使用静态检查或针对性命令。
- 未运行、跳过或失败的检查必须如实报告。

## 工具偏好

- 【跨项目稳定存在的工具或命令偏好。】
- 【特定任务的工具选择及触发条件。】

## 安全边界

- 删除、覆盖、提交、推送、发布或外部系统变更前需要【授权要求】。
- 与当前任务无关的既有改动不得覆盖、回退或清理。
- 不读取、写入或泄露【凭据、令牌、私钥或其他敏感数据范围】。
```

## 删除项

最终文件不得包含 `【】` 占位符、示例说明、项目专属命令或路径、一次性防御规则、不可验证的常识，以及与系统或工具内建能力重复的内容。

## 维护方法

- 只在个人偏好真实变化时更新，并同步删除重复或低价值规则。
- 项目事实和项目专属规则以仓库内项目级 `AGENTS.md` 为准。
- 规则维护、审阅、备份和新上下文验证使用按需的 `agents-maintenance` Skill。
